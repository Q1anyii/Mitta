# Agent 记忆与状态管理

> 基于 AgentProject 项目总结，涵盖记忆分类、短期/长期记忆实现、画像提取与增量合并、
> 记忆更新策略与性能，以及 Mitta 双层记忆体系的实际实现与实测口径。

## 一、Agent 记忆分类

| 记忆类型 | 生命周期 | 存储 | 典型实现 |
|----------|----------|------|----------|
| 工作记忆（上下文） | 单次会话 | LLM 上下文窗口 | 消息历史列表 |
| 短期记忆 | 会话级 | 数据库/缓存 | 按会话入库的对话记录 |
| 长期记忆 | 跨会话 | 向量库/关系库 | 用户画像、知识条目 |
| 情景记忆 | 跨会话 | 事件日志 | 用户行为记录 |
| 语义记忆 | 持久 | 知识库 | 领域事实、规则 |

**核心问题**：上下文窗口有限，记忆必须**筛选、压缩、按需召回**，不能全量塞入。

## 二、记忆读写链路

```
对话轮次 → 提取关键信息 → 写入记忆存储 → 生成前召回 → 并入 System Prompt / 上下文
```

关键设计决策：
1. **写什么**：不是所有对话都值得记，由 LLM 判断"值得沉淀的画像/事实"
2. **存哪**：短期按会话、长期按用户维度隔离
3. **何时取**：生成前把相关记忆并入上下文，且不喧宾夺主
4. **如何更新**：增量合并（更新而非覆盖），保留历史积累

## 三、Mitta 双层记忆实现

### 3.1 架构

```
短期记忆（Session）
  └─ 每轮对话上下文按会话入库，保证多轮连贯
长期记忆（User Profile）
  └─ 按用户维度，由 LLM 每轮自动提取画像并增量合并
  └─ 生成前并入 System Prompt 补充上下文
```

- **短期记忆**：对话历史按会话组织，提供多轮追问所需的上下文
- **长期记忆**：跨会话沉淀用户偏好/身份/事实，写入前由 LLM 判断是否值得记忆

### 3.2 画像提取与增量合并

```python
# 每轮由 LLM 提取可沉淀的画像条目
profile_items = llm_extract(state)   # 结构化：新增/更新/冗余
# 增量合并：更新而非覆盖
user_profile = merge_profile(user_profile, profile_items)
```

- **更新而非覆盖**：新信息与旧画像合并，避免丢失历史积累
- **重复抑制**：重复内容自动跳过，三轮写入可抑制掉一半冗余写入
- **写入解耦**：长期记忆更新与主对话生成解耦（fire-and-forget），不阻塞回复

### 3.3 实测口径（生产容器内）

| 指标 | 数值 | 口径 |
|------|------|------|
| 长期记忆写入 P95 | **3.01 ms** | docker exec 进容器直连 Postgres，3 轮中位数 |
| 长期记忆读取 P95 | **2.09 ms** | 同上 |
| 生产链路读写 | **P95 ≤ 5 ms** | 容器内全链路 |
| 历史本机基线 | 4.56 / 2.49 ms | n=5/20，仅本机对照 |

> ⚠️ 口径纪律：对外只报**生产容器内** 3.01/2.09；公网直连对照（28.00/51.87 ms）只用于解释公网 RTT，不是生产延迟；旧的"46 ms"已作废（含连接池冷启动）。

## 四、记忆更新策略

### 4.1 什么值得记

- 用户显式陈述的偏好、身份（"我是后端开发"）
- 跨轮重复出现的主题（可能重要）
- 任务相关的关键事实（项目名、环境）

### 4.2 什么不该记

- 一次性指令（"帮我查一下今天的天气"）
- 敏感信息（密码、token）——默认不沉淀
- 临时上下文（"这次用这个文件"）

### 4.3 更新时机

- 每轮对话后异步提取（不阻塞主流程）
- 冲突时新信息优先，但保留历史版本便于审计
- 定期清理过期/冗余画像条目

## 五、记忆与状态管理的关系

- **状态（State）**：单次执行内的数据传递（LangGraph 的 StateGraph 状态累积）
- **记忆（Memory）**：跨执行的持久化（会话、用户维度）
- Mitta 中：状态负责主图内节点间传递（问题、改写查询、候选文档），记忆负责跨轮/跨会话沉淀

## 六、FAQ

**Q1：记忆写入会拖慢回复吗？**
取决于是否同步。Mitta 将长期记忆更新设计为 fire-and-forget（与生成解耦），正文流完即结束加载态，记忆写入在后台完成，不阻塞首 token。

**Q2：怎么判断一条信息"值得记"还是"临时的"？**
用 LLM 判断 + 规则过滤：① 是否含用户持久属性（身份/偏好）；② 是否跨轮重复；③ 是否敏感（不记）。拿不准就交给用户显式确认，宁缺毋滥。

**Q3：多用户记忆如何隔离？**
按用户维度做键隔离（如 user_id 维度），读取时只召回当前用户的画像；跨会话共享的知识进知识库（RAG），不进个人画像，避免串味。
