# Agent 评估与可观测性

> 基于 AgentProject 项目总结，涵盖评估体系分层、RAGAS 指标、Agent 链路评测、
> 评测集建设与回归测试、成本与延迟评估，以及 Mitta agent_test 全量评测的实际实现与口径。

## 一、评估体系分层

| 层级 | 评估对象 | 典型指标 | 频率 |
|------|----------|----------|------|
| 组件级 | 单个节点（路由/检索/工具/记忆） | 准确率、召回率、命中率 | 每次改动 |
| 链路级 | 检索子图、生成链路 | recall、answer correctness | 每次改动 |
| 系统级 | 端到端问答 | 忠实度、相关性、成本、延迟 | 周期回归 |
| 生产级 | 线上真实流量 | 首 token、错误率、缓存命中 | 持续监控 |

**原则**：先在组件级定位问题，再在链路级验证整体效果；指标必须可复现、有基线。

## 二、RAGAS 核心指标

RAGAS 是 RAG 评估的主流框架，核心指标：

| 指标 | 衡量 | 说明 |
|------|------|------|
| Faithfulness（忠实度） | 答案是否忠于检索内容 | 防幻觉核心指标 |
| Answer Relevancy（答案相关性） | 答案是否切题 | 生成质量 |
| Context Precision（上下文精确率） | 召回内容是否相关 | 检索质量 |
| Context Recall（上下文召回率） | 必要信息是否被召回 | 检索完整性 |
| Context Entity Recall | 实体级召回 | 事实覆盖 |

**实践要点**：
- RAGAS 指标适合**离线评测集**（每问标注理想上下文/参考答案）
- LLM-as-judge 有成本与波动，指标对比要用同一批次、同参数
- 单条波动大，看**中位数与分布**而非只看均值

## 三、Agent 链路评测（Mitta agent_test）

Mitta 将原 `ragas_test` 改造为面向整个 Agent 系统的 `agent_test`，按组件 + 链路覆盖：

| 评测 | 对象 | 现役口径 |
|------|------|----------|
| E1 统一路由 | 意图分类 + 人格分类 | 37 条，意图 91%~94%（区间），人格 32/32=100% |
| E2 工具筛选 | 规则+语义并集召回 | 41 工具/22 用例，recall 0.8939、零空结果 |
| E3 工具装配 | 装配链 | 6/6 |
| E4 MCP 安全 | 白名单/包名/敏感变量 | 11/11 拦截 |
| E5 工具失败熔断 | 熔断与恢复 | 13/13（连续失败 2 次摘除等） |
| E6 缓存 | 语义缓存命中率 | 隔离 97.2%、混合 61.1%~88.9%（按候选数） |
| E7 检索 | 混合检索质量 | boolean 命中率均值 0.81、中位数 1.0、零空结果 |
| E9 记忆 | 读写性能 | 生产容器内写 P95 3.01 / 读 P95 2.09 ms |

## 四、评测集建设

### 4.1 来源与标注

- 真实对话记录 + 人工标注（意图标签、理想文档、参考答案）
- 边界用例专项建集：易混淆 query、同义改写对、硬负样本（Mitta 缓存硬负 8 条 + 跨域 6 条）
- 规模宁可小而准，不可大而糙（每条都要能人工核对）

### 4.2 防止评测集"过拟合"

- 评测集与调参集分离（训练/验证/测试）
- 同一 query 多轮重跑看波动（temperature=0 下 LLM 仍有采样差异，报区间）
- 新用例持续补充，旧用例回归

## 五、成本与延迟评估

| 指标 | 说明 | Mitta 实测 |
|------|------|------------|
| 首 token 延迟 | 用户可感知的关键指标 | 短路 p50 1608ms、检索类 12.3s（已用预响应优化） |
| 单次成本 | token 消耗 | 缓存命中跳过检索子图，embedding 调用降 12.5% |
| 缓存命中率 | 成本与延迟杠杆 | 61%~97%（按场景） |
| 工具调用轮次 | 上限控制（MAX_TOOL_ROUNDS=8） | 防失控循环 |

**口径纪律**：数字必须带场景（生产容器内 / 公网对照 / 离线评测），同一数字跨文档一致；旧口径作废要说明原因（如基线选错、计数重复）。

## 六、回归测试与 CI

- **组件级回归**：每次改动跑相关评测（快，秒级~分钟级）
- **全量回归**：周期跑（RAGAS 类 LLM 评测耗时高，不进每次 CI）
- **快慢分离**：确定性断言（规则/统计）进 CI 门禁，LLM-judge 走定时任务
- **报告归档**：评测报告按日期归档（`src/agent_test/reports/<日期>/`），可对比历史

## 七、FAQ

**Q1：为什么统一路由准确率只报区间（91%~94%）而不是单点？**
两次 temperature=0 重跑仍有 1 条 query 的投票从 2:1 变 3:0，说明采样存在波动。报单点会给人"精确"的假象，报区间才是真实口径——被追问也能解释清楚。

**Q2：RAGAS 指标能直接用于线上监控吗？**
不适合高频监控（LLM-judge 贵且慢）。线上用**可观测指标**（检索命中率、缓存命中率、首 token、错误率），RAGAS 类指标走离线周期评测。

**Q3：评测集越加越多，怎么管理成本？**
分层：核心集（每次回归）+ 扩展集（周期回归）+ 候选集（人工审核后晋升）；RAGAS 只跑核心集，确定性指标跑全量。
