# Agent 工具调用与 MCP

> 基于 AgentProject 项目总结，涵盖 Function Calling 原理、MCP 协议、工具注册与安全校验、
> 失败熔断与降级，以及 Mitta 第三方 MCP Server 免改代码接入的实际实现。

## 一、Function Calling 原理

Function Calling 是模型与外部工具的**接口机制**：模型根据工具描述输出结构化的调用意图（工具名 + 参数 JSON），由代码执行真实调用。

```
系统：可用工具 get_current_time()
用户：现在几点了？
模型：[tool_call] get_current_time(tz="Asia/Shanghai")
代码：执行工具，返回 "2026-09-21 10:30:00"
模型：现在是 2026-09-21 10:30。
```

**实现要点**：
- 工具 schema 必须准确（名称、参数类型、必填项、描述）
- 模型输出的是"调用意图"，**执行权在代码**——可以做权限校验、白名单拦截
- 工具返回结果要回喂给模型，形成闭环

## 二、MCP（Model Context Protocol）

MCP 是**工具接入的标准协议**，解决"每个 Agent 框架都要写一套工具适配"的重复劳动：

| 角色 | 说明 | Mitta 对应 |
|------|------|------------|
| MCP Server | 提供工具能力（stdio / SSE 传输） | mcp-server-fetch、markitdown、chroma、basic-memory 等 |
| MCP Client | 发现并调用 Server 的工具 | `mcp_client` 模块（连接、发现、调用、健康检查） |
| 工具注册表 | 聚合所有可用工具给 LLM | 规则层 + 语义层并集索引 |

### MCP 接入流程

```
1. JSON 配置注册（server 名、命令、参数、传输方式）
2. 客户端拉起子进程 / 连接 SSE，握手
3. 发现工具列表 → 写入工具注册表
4. LLM 选择工具 → 调用 → 结果回传
5. 失败重连 / 健康检查跳过
```

### Mitta 实现要点（基于项目真实代码）

- **免改代码接入**：第三方 MCP Server 通过 JSON 配置注册（`mcp_servers.json`），不改一行代码即可扩展工具
- **连接管理**：`_connect_one` 逐个连接，单个失败**跳过不阻塞**（如 markitdown/chroma 连接失败仅 WARNING，其余照常）
- **健康检查**：服务启动时对 MCP 工具做健康探测，失败多次即标记不可用，避免运行期才暴露
- **超时控制**：MCP 调用超时调至 120s（长任务工具需要足够执行时间，短超时会导致误判失败）

## 三、工具安全校验（Mitta 安全层）

工具能操作外部世界，安全校验是 Agent 的**生死线**。Mitta 内置四道校验（评测 11/11 通过）：

| 校验 | 说明 |
|------|------|
| 命令白名单 | 只允许执行白名单内的命令，拦截任意命令执行 |
| 包名校验 | 校验工具安装/执行的包名合法性 |
| 敏感变量拦截 | 拦截读取敏感环境变量（如 API Key、密钥） |
| type/协议校验 | 校验 MCP 传输类型与协议合法 |

**为什么需要工具级白名单而不是信任模型**：模型可能被提示注入诱导调用危险工具（如"执行 rm -rf"），白名单在**执行层**兜底，不依赖模型判断。

## 四、失败熔断与降级

工具调用失败是常态（网络、参数、权限），Agent 必须优雅处理：

```
失败计数：工具连续失败 +1，成功则清零
熔断阈值：MAX_TOOL_FAILURES = 2（连续失败 2 次摘除）
摘除后：该工具从本轮可调用列表移除，其余工具照常
全熔断：所有工具不可用时明确提示，不假装成功
```

**实测口径（E5 评测）**：13/13 通过，覆盖场景：
1. 连续失败 2 次 → 摘除工具
2. 成功后计数清零 → 工具恢复
3. 自我强化提示排除（失败提示中不重复诱导调用）
4. 全熔断时点名提示"本轮已连续失败、暂时不可用"

**配套设计**：
- **结果后处理**：工具返回做长度截断（如 200 字），防止超长输出撑爆上下文
- **异常兜底**：工具抛异常转成可读错误信息回喂模型，让模型换路
- **降级**：语义工具召回失败自动降级规则层，不阻塞主对话

## 五、FAQ

**Q1：工具超时设多少合适？**
取决于工具特性：普通查询工具几秒内返回，可设 10-30s；重任务（文档转换、长网页抓取）需 60-120s。Mitta 将 MCP 超时调至 120s，避免长任务被误杀；配合健康检查前置，不拖慢主链路。

**Q2：如何防止工具被提示注入利用？**
① 执行层白名单兜底（命令/包名/敏感变量）；② 工具描述中声明"仅执行用户明确授权的操作"；③ 敏感操作需用户二次确认（双钥匙机制）；④ 对工具返回内容视为不可信数据，不直接拼入提示词执行。

**Q3：工具返回结果太大怎么办？**
截断 + 摘要：长文本截断保留关键部分；结构化结果只保留必要字段；必要时让 LLM 先对结果做摘要再入上下文。
