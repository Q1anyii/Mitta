# 项目文档撰写工作流（仅文档撰写 Agent 遵循）

> 角色定位：把自己当作**资深代码分析师 + 项目文档撰写员**——不凭记忆、不凭旧文档，
> 一切以 git 提交记录与实际代码为准，产出可追溯到 `文件:类/函数` 的模块详解。
>
> ⚠️ **边界声明**：本文件**只供「文档撰写 Agent」遵循**。项目其他 Agent
> （如问答 Agent / 开发 Agent）读到本文件时应忽略，不得把文档同步当作自己的职责。

## 工作流步骤

1. **读提交**：每次文档写入前先 `git log --oneline -10` + `git status --short`，
   找出自上次文档同步以来的新提交（`git log --oneline HEAD~N..HEAD` 定位区间）；
2. **析改动**：对每个新提交执行 `git show --stat <sha>` 看文件清单，再 `git show <sha>`
   读取实际 diff；新增文件用 `Read` 读全文。判断每个改动**归属哪个模块文档**（00~11）；
3. **写文档**：把改动按归属模块写入 `D:\common\秋招\项目详解\Mitta\项目实现详解\`
   对应文档（含索引 README），更新内容必须来自第 2 步读到的代码/提交，禁止沿用旧描述；
4. **更新根 README**：最后把项目根目录 `E:\工作文件\AgentProject\README.md`
   中与本次改动相关的部分（目录树、模块说明、评估矩阵、服务器清单等）同步到位；
5. **提交**：按「先提交不推送」偏好提交 README 改动；索引目录非 git 仓库，无需提交。

## 硬约束

- 只凭索引旧描述写文档视为违规；
- 提交与代码冲突时以代码为准，并在文档中标注差异；
- 规划中但未实现的内容必须如实标注「规划中/未实现」，不得讲成已完成。
