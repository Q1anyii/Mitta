# ci-flow.html 交互式流水线改造——分支闪烁流动 + 修复判定推进逻辑（H-20260924-03）

docs_sync: none

日期：2026-09-24
类别：ci / docs-visual

## 背景

`docs/ci-flow.html` 原为静态 SVG 流程图，用户要求改为「像流水线一样」的交互演示：点击菱形判定节点后，其两条分支线闪烁流动、光点沿线运动，选择分支后沿流水线自动推进到下一判定；同时整体可视化要更美观、一屏装下。

## 改动（`docs/ci-flow.html` 重写）

1. **流水线动态动画（SMIL）**：
   - 判定节点进入待决（pending）时，两条出口分支线变为红色虚线（`stroke-dasharray="12 9"`），叠加 `<animate stroke-dashoffset>`（21→0 循环）实现虚线向箭头方向流动 + `<animate opacity>`（0.4↔1）实现脉冲闪烁，并在分支线上加黄色光点 `<circle>` + `<animateMotion>` 沿线流动；
   - 已走过（walked）的边保持深色实线 + 白色光点缓流（1.4s），形成"流水线"延续感；
   - 未涉及边浅灰静态，降低视觉噪音。
2. **可视化美化**：
   - 节点：按语义色 8 组线性渐变填充（visited 态）+ `feDropShadow` 投影 + 判定选中分支后实色绿/红；
   - 泳道：4 段（回归门禁 / 构建与同步 / 入库与部署 / 校验与回滚），左侧加白底胶囊阶段徽章；
   - 分支标签（是/否/通过/失败）：白色胶囊底 + 选中后深色反白，可读性提升；
   - 容器背景微渐变，控件行徽章化。
3. **交互逻辑修复（重要 bug）**：
   - `onNodeClick` 原逻辑校验「存在 `last→id` 的边」才允许进入待决。但 advance 推进到判定节点后 `last` 就是该判定节点本身（如 `buildq`），需要点它自己——条件永远不成立，导致**交互只能推进一层**（旧版同样存在，实测停在「重建镜像？」）。
   - 修复：`id === last` 时直接进入待决，保留后继校验分支兜底。
   - `rollback` 由 action 改为 decision（label「回滚成功？」）：原为多出口 action，advance 遇多出口会卡死且用户无法选择回滚成败；改判定后用户可继续选「成功→部署成功 / 失败→回滚失败」。

## 验证

- browser-use 实测四条路径全部走通：成功主链（gate 是→buildq 是→blueq 否→health 是→部署成功）、回归失败（gate 否→红叉终止）、回滚失败（…→health 否→rollback 否→exit 1）、回滚成功（…→rollback 是→部署成功）；
- pending 状态检查：分支线 `<animate>` 4 个（两条线各 dashoffset+opacity）、光点 2 个、是/否按钮出现、状态栏提示闪烁；
- 页面无 JS 错误（仅 file:// 协议下 favicon 404，无关）；viewBox 1200×520，页面高度约 590px，一屏装下无滚动；
- 静态降级：无 JS 或 SMIL 不支持时，节点/边/分支标签的静态结构完整可读（动画仅是增强）。

## 风险与遗留

- SMIL `<animate>`/`<animateMotion>` 在部分渲染器（截图工具、某些浏览器降级模式）不呈现动画，但静态高亮逻辑仍在；
- 窄视口（<700px）下 SVG 整体缩放、文字随之变小——真实桌面窗口（≥1280px）清晰；如需移动端可后续改为按视口切换两套布局；
- `docs/_refresh-arch.html`（刷新不断流机制交互演示）已创建但未在本轮浏览器实测，后续可补测。
