## 背景

用户决定放弃 RAGAS 全量重跑（225 项评分约 1 小时+，10 条小样本又无法保证准确率），
采用 README 中自建评测集的**历史指标 0.7732**（E7 混合检索 top-5 recall 中位数）。

为确认 0.7732 是否仍可复现、是否需要更新，重跑 `eval_retrieval.py`（45 条刁钻 QA）。

## 重跑结果（当前环境）

| 指标 | 历史（954b8bf, 8/23） | 当前重跑 |
|------|---------------------|---------|
| 单路 avg recall@5 | 0.6837 | 0.2774 |
| 单路 median recall@5 | 0.7113 | 0.2000 |
| 混合 avg recall@5 | 0.6553 | 0.2233 |
| 混合 median recall@5 | **0.7732** | 0.1546 |

## 排查过程（排除法）

| 排查项 | 结论 |
|--------|------|
| 评测脚本 eval_retrieval.py | HEAD 与历史版本 **diff 为空**（完全相同） |

| 知识库源文件（10 个 md） | git 对比 **全部 SAME** |

**无法解释单路 recall 0.71 → 0.20 的差异**——排除脚本/数据/模型后，
唯一剩余变量是 **ChromaDB 向量库入库状态与 8/23 不同**（git 不跟踪 chroma，
无法回溯；9/18 重新入库覆盖了历史向量库）。

## 顺带发现的真实 Bug（已修复）

`eval_retrieval.py` 的 `bm25_search` 与生产 `query_nodes.py` 不一致：

| 问题 | 生产 query_nodes.py | 评测 eval_retrieval.py（修复前） |
|------|--------------------|--------------------------------|
| jieba 分词拼接 | OR（`\|`） | **AND（空格）→ 中文多词必 0** |
| redis-py 8.x 返回 | dict 兼容 | **只认 list → 全空** |
| Redis 指向 | 6379（RedisSearch） | **.env 6380（无 RedisSearch）** |

已把 eval_retrieval.py 同步为与生产一致（OR 拼接 + dict 解析 + 注入 6379）。
修复后 BM25 实测可正常返回（如 "bcrypt 密码加密如何实现" → 3 条命中）。

## 决策（用户指定）

- **README E7 保留 0.7732，标注「历史产物」**（用户决定放弃 RAGAS，采用旧指标）
- `retrieval_eval_report.json` 已恢复为历史 0.7732 版本，与 README 一致
- **风险提示**：当前环境重跑无法复现 0.7732（实测 ~0.15-0.20），
  对外口径若被追问复现方式，需说明为历史评测值；建议后续若要上线该指标，
  需还原 8/23 向量库入库状态或用当前可复现口径重新定义。

## 遗留

- 若未来要恢复 0.7732 的可复现性，需要：还原历史向量库（不可得）或
  重新设计评测口径（如改为关键词命中率 / 文档级召回 / 减小 ground_truth 粒度）
- 混合检索过滤阈值 0.15 对重排分数分布敏感，部分 query 过滤后仅剩 1-3 个文档，
  导致 recall@5 受限——可作为后续优化方向（阈值校准或兜底策略）
